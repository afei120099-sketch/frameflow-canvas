# 长剧本分段规划 V0.1

入口：夜班 → M2 AI导演计划 → 长剧本：分段制作。

1. 粘贴完整剧本，复制章节规划任务给用户选择的 GPT / Claude。
2. 将纯 JSON 粘回来，检查版本、原文覆盖顺序、章节数量、需求长度和时长。
3. 人工核对各段需求是否保留台词和叙事、人物与场景连续性。
4. 保存章节到项目制作进度板（也可下载 JSON）；在成片序列关联已有镜头。再载入一段需求，使用原有导演任务 → 导入检查 → 人工确认制作流程。

## 边界

- 不是自动长片导演。没有调用新 Provider，没有模型安装、GPU 自动启动、任务批量排队或跨段自动合成。
- 单次制作仍使用既有 M2 的 15–60 秒、3–6 个文生视频镜头限制。最多 40 章、原剧本 30000 字符；超限拒绝，绝不截断。
- 章节原文逐字拼接核对只保证不漏原文，不保证 AI 的 brief 语义完整；这仍需人工审批。
- 连续性字段用于人工核对，不自动注入生成 Prompt。请在原入口维护主体锚点、约束和批准事实；不能承诺跨段人物精确一致。
- 载入章节会替换当前需求和时长、清空待导入导演计划，保留题材、锚点及约束。不会创建或修改 Shot / Run / Asset。
- 未保存输入仅在打开的面板内保留。已保存计划、参考建议、章节镜头绑定和连续性记录在现有 meta 数据内，随项目备份恢复；夜班磁盘输出仍需独立夜班归档。
- 参考视频可本地 CPU 解码抽帧并导出联系表，复制分析任务给用户选择的 GPT / Claude；语义分析需要另附图片并人工核对。不是自动理解视频或画面质量判定。未复制或安装 OpenMontage。

## 测试

运行 `npm run test:story-chapters` 检查覆盖顺序、遗漏、重复及长度限制。
