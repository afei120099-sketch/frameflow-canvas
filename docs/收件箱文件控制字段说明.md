# 收件箱文件控制 v2 字段说明

版本：2026-10-21。是否已上线请看根 `_control_status.json` 的 `fields`、`fileOperations` 和更新时间；仅有本说明不代表已启用。用户只改文件，程序内部正常核对/保存 IndexedDB。不要手改状态文件或数据库。画布程序须保持运行，但不要求用户点界面。

## 1. 文件位置和完整示例

根目录：由环境变量 `FRAMEFLOW_INBOX_ROOT` 指定（默认 `./data/inbox`）。控制文件 `_control.json`：

```json
{
  "autoEnqueue": true,
  "autoChain": true,
  "submit": true,
  "stopSessions": [],
  "pauseSessions": [],
  "priority": [],
  "interruptRunning": [],
  "rerunShots": [],
  "skipShots": [],
  "retry": {"maxRetries": 1}
}
```

示例中的空数组不代表要清空你原有的 stopSessions；修改时保留旧停止列表。文件必须是合法JSON，无注释。约4秒读取，错误配置禁止新提交并报告错误。空跑校验始终可用。

| 字段 | 格式、默认值 | 作用与示例 |
| --- | --- | --- |
| autoEnqueue | 必填boolean | 自动入队/主镜头提交；false不取消已接单任务。 |
| autoChain | 必填boolean | 自动接尾帧和尾帧高清；false暂停未提交续段。 |
| submit | 必填boolean | 画布所有新ComfyUI提交的总闸。 |
| stopSessions | sessionId字符串数组，默认[] | 永久停止指定批次；例如["某批ID"]。保持既有停止规则，移除ID也不自动恢复。 |
| pauseSessions | sessionId字符串数组，默认[] | 暂停指定批次。当前镜头保留；已排队但未执行的本批任务保存完整原工作流并移出等待队列，未提交镜头等待。移除ID后按原prompt_id核对恢复，不建替代Run。 |
| priority | sessionId字符串数组，默认[] | 从前到后优先，第一项最高；例如["B批ID","A批ID"]。未运行的目标任务可排到其他批次前面；运行中的任务不被抢占。依赖必须先满足，插队不会凭空生成上游帧。 |
| interruptRunning | sessionId字符串数组，默认[] | 显式中断该批当前唯一匹配的运行任务。不使用全局interrupt，不支持精确取消的服务报错而不误伤其他任务。每次请求消费一次，保留ID不会连杀下一镜。 |
| rerunShots | 选择器数组，默认[] | 显式重渲，保留旧产物。标题必须完整、唯一。原任务须有可核实终态；运行/排队/不明任务拒绝。 |
| skipShots | 选择器数组，默认[] | 跳过指定镜头。依赖它的后续镜头标为等待上游，不跟着静默跳过。已完成产物保留；当前正在运行的镜头不以skip冒充中断。移除后可重新判断剩余计划。 |
| retry.maxRetries | 0–10整数，默认1 | 每批每镜最多额外自动重试N次，0关闭。只对功能启用后新发生、原history明确失败的任务生效；取消/删除/停止/提交不明不重试。保留全部Run、错误原文及原history。额度按节点累计，刷新不重置。 |

`STOP`：同根目录无扩展名文件，临时暂停全局未提交工作，删掉后恢复仍有授权的计划。不会清空 stopSessions，不能复活停止/取消/删除任务。直接从ComfyUI自身界面提交的任务不由画布总闸控制。

画布左下角「收件箱」开关和手改文件是同一套：「自动入队 开/关」只改 `_control.json` 的 autoEnqueue，「急停 / 解除急停」就是建 / 删 `STOP`。

## 2. 单镜选择器

```json
{
  "sessionId": "目标批次ID",
  "titles": ["L06 完整镜头标题", "L07 完整镜头标题"],
  "cascade": false,
  "requestId": "rerun-20261021-001"
}
```

将该对象放在 rerunShots 数组内。cascade:false只重渲选中镜头，已完成的下游视频不改变；cascade:true沿首帧、尾帧、延长依赖递归纳入下游，并在上游新版本完成后取新帧。原尾帧缓存不会误复用。标题不存在/重复、已删节点或已取消任务均拒绝，不能把重渲当作恢复删除。

requestId建议显式填写，每次真正要再做一次时换一个新ID。同一ID只消费一次；省略时按选择器内容生成ID，相同内容不会每4秒重复渲。accepted表示原会话接受操作意图，不等于GPU接单或完成；须看新Run/promptId/产物。状态不明不补交。

interruptRunning中的ID保持不动只请求一次；需要以后再中断同一批的另一个运行镜头时，先移除ID，等一次扫描确认，再重新加入。移除只重新允许新的中断命令，不清除永久停止记录。

skipShots示例：`[{"sessionId":"目标批次ID","titles":["L06 完整镜头标题"]}]`。skip不递归跳过下游，cascade字段对skip不生效；下游显示waiting_upstream。

## 3. 队列自动切页

在shot-queue-v1队列JSON顶层添加：

```json
"autoSwitchPage": true
```

默认false。仅切到实际存在的目标页；切换前让原提交控制器让出，并通过真实保存确认。保存不成功时写等待/错误，不绕过、不清数据库、不创建替代页。已接单任务仍由原Run恢复查询。文件命令定位的原会话按sessionId核对，不用新队列替换它。

## 4. 状态、编译报告和小图

根 `_control_status.json` 包含原开关/effective、逐批停止和暂停、优先级，以及新字段观测值与 `fileOperations.effects`。observed只表示读取成功，不等于动作完成；waiting_page/waiting_controller表示等待，accepted表示接受，rejected/error/uncertain需核对。报告停更时先看updatedAt，不能当实时状态。

每项目 `_batch_<sessionId>.json` 包含逐镜标题、状态、nodeId、runId、promptId、提交/开始/结束时间、durationMs、输出文件名/assetId/storageReference、完整编译提示词compiledPrompt、Picture表pictures、Subject表subjects、依赖链dependencies、实际取帧来源frameInputs，以及所有历史attempts。retryHistory保存自动重试原错误和ComfyUI原history；不会覆盖旧Run。

submittedAt记录正向接单回执的观测时间，submittedAtSource为acceptance_observed；旧任务未记录时是null/not_recorded，不用预留Run的reservedAt冒充提交时间。无时间证据不编造用时。同页的历史批次可经原session受控激活，但冷启动不会默认续跑归档批次；有永久停止证据始终拒绝。

每镜完成后用浏览器CPU解码原视频，仅把小JPG写入项目目录：

```text
_frames\清理后的标题_镜号\<runId>\first.jpg
                                  last.jpg
                                  25.jpg
                                  50.jpg
                                  75.jpg
                                  sheet.jpg
_frames\清理后的标题_镜号\sheet.jpg
```

单张宽至多640，保持比例。sheet为2×2，依次首帧/25%/50%/尾帧；75%单图仍保留。runId子目录保留旧版本，标题目录sheet为最新预览。实际路径写在batch.frames中，不上传/改写MP4，不花GPU。解码失败在fileOperations中报告，不能冒称抽帧完成。

`_events.jsonl`追加批次/镜头状态变化，含at、eventId、revision、sessionId、Run及错误。暂停/恢复、失败/完成、停止、实际续接来源变化都会留下事件；相同观测不重复追加，不截断原日志。

`*_validate.json`和validateOnly:true额外写 `_compiled_<源文件名>.json`，含逐镜prompt全文、实际可解析的Picture/Subject表、assets解析及缺失项、依赖来源、over12000镜头列表。动态首尾帧在视频产生前只能标deferred，不能把占位编译称为最终提交；实际提交表以batch中Run的冻结记录为准。超过12000字符仍按现有schema拒绝，不截断，不另加4000风险线。

## 5. 安全约束

### 画布心跳（2026-10-22）

根 `_control_status.json` 的 `canvasHeartbeat` 包含 `observedAt`、`ageMs`、`timeoutMs:120000`、`stale`、`state`（fresh/stale/unknown），另有便于脚本读取的 `canvasHeartbeatStale`。Node服务每4秒根据最后一次真实 `canvasObservedAt` 更新年龄；不会伪造画布心跳。`updatedAt` 可以因服务端巡检更新，不能替代 `canvasObservedAt`。前端锁屏/冻结/关闭超过120秒标为stale，不据此重试GPU或判完成。服务端也关闭时文件无法自行更新，巡检还需检查文件更新时间/接口是否在线。

会话确认等待阈值为10分钟，未收到回执进入 `awaiting_session`，保留原请求继续观测；迟到会话认回，不因超时自动重提交。已知原session暂不可核实仍blocked，不能改为新建任务。历史90秒超时记录可在原会话迟到时重新核对认回；如果确实从未启动，需要唯一 `retry_handoff` 命令及实时安全核对。

停止优先于暂停/优先级/重渲/重试；已取消和删除任务不复活。所有新功能不删原素材、原视频或历史产物。暂停/优先级只操作证据明确且属于该session的等待任务，不清全局队列；任务抢先进入运行或历史已有记录时认回，不重复提交。取消、移出队列、恢复回执不明时停在uncertain，而不是猜测成功。
