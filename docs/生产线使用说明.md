# 生产线（整集批量）使用说明

2026-11-08 新增。入口：画布顶栏「生产线」，或 Ctrl+K 搜「生产线」，或浏览器打开 `http://localhost:<画布端口>/__production/`。**每个画布有自己的生产线**：从哪个画布打开，就只看到、只新建那个画布的剧；新建的画布也自动有。让别的 AI 帮你写剧集 JSON：点页面上「复制给 AI 的说明」，或把 [生产线-AI接入说明.md](生产线-AI接入说明.md) 发给它。

## 它解决什么

把一集短剧按镜头排成流水线，让抽卡发生在便宜的关键帧阶段：

```
分镜图 → 关键帧（每镜默认 3 张，自动按人脸打分）→ 你点「通过」→ H3 视频（只用通过的关键帧当首帧）→ 你点「选定」→ 合成成片
```

- **后台执行**：执行器只有一个，跑在主画布（5173）开发服务进程里，所有画布的剧共用它、轮流用显卡；和夜班一样，关掉画布标签页也继续。主画布没开时其他画布的生产线会提示。
- **不抢 GPU**：ComfyUI 里有画布或其他任务时生产线一律等待；同一时间只提交一个生产任务。
- **按模型分批**：正在出关键帧（Flux）就先把关键帧出完，再切到视频（H3），减少反复加载模型。
- **听根控制**：收件箱根目录放 `STOP` 文件，或 `_control.json` 写 `"submit": false`，生产线也停止提交新任务（已在 ComfyUI 的继续跑）。
- **不会重复生成**：任务 ID 先写盘再提交；提交时断线就去 ComfyUI 查原任务，绝不凭猜测重提。ComfyUI 重启导致查不到时，这一集暂停，等你点「重新提交」或「放弃」。

## 第一次使用

1. 点「＋ 新建」，点「填入模板」，改成你的剧集，保存。
2. 弹出「素材」：把分镜图、角色脸、角色全身图拖进去。**文件名要和剧集里写的一样**。
   画布里已经建好的角色不用导出文件：从画布顶栏点「生产线」打开页面，在「新建 / 编辑剧集」里点「从画布导入角色」，勾选角色，保存时自动上传它的脸部参考（没有就用主外观）、主外观图和主声音。只读，不改画布。
3. 点「出关键帧」。每镜出 `keyframe.candidates` 张，完成后自动算人脸相似度（脸 0.60 以上绿色，0.45–0.60 黄色，以下红色）。
4. 每镜挑一张点「通过」（点图片可以和分镜图、深度图并排看）。不满意点「＋ 再出 3 张」。
5. 点「出视频」：只给已通过关键帧的镜头出 H3 视频。鼠标移上去预览，满意点「选定」。
6. 每一镜都选定后点「合成成片」，按镜头顺序硬切，文件在 `runtime/production/<剧集ID>/output/`。

## 剧集格式（production-episode-v1）

| 字段 | 说明 |
| --- | --- |
| `title`、`aspect` | 标题；`9:16`（关键帧 864×1536）或 `16:9` |
| `roles[]` | `key`（英文 ID）、`name`、`description`（稳定身份描述）、`face`（关键帧锁脸用的脸部图）、`appearance`（第 1 张是给 H3 的主外观图）、`voice`（主声音 wav/mp3，对白用） |
| `keyframe.look` | 全集共用的外观描述，**英文、只写要什么** |
| `keyframe.depthStrength` | 分镜深度控制强度，0.3–1.5，默认 1 |
| `keyframe.candidates` | 每镜出几张，1–6，默认 3 |
| `keyframe.autoApproveAbove` | 填 0.3–0.95 的数则自动通过人脸分最高且达标的那张；`null` = 全部人工审 |
| `video.tuning` | `default`（原 10 步，快）或 `understanding`（去加速 LoRA、25 步、关稀疏；实测多动作镜头时间点更准，耗时约 1.5–2.3 倍） |
| `video.soundMode`、`megapixels`、`candidates` | 声音 av/ambient/silent；像素预算 0.3–1；每镜出几条 |
| `shots[].storyboard` | 这一镜的分镜图文件名（决定构图、机位、站位、姿态） |
| `shots[].faceRole` | 关键帧锁谁的脸；`null` = 空镜或群演不锁 |
| `shots[].faceWeight` | 锁脸强度，默认 0.85；仰拍/俯拍可降到 0.5–0.6 |
| `shots[].keyframePrompt` | 这一镜的外观补充，英文 |
| `shots[].videoPrompt` | H3 提示词，和画布队列写法一样；`<Picture 1>` 是通过的关键帧，之后是 `roles` 里各角色的外观图 |
| `shots[].roles`、`seconds`、`seed` | 本镜角色（主外观图和声音交给 H3）、5–15 秒、固定种子 |
| `shots[].dialogue` | 和画布队列一样：`{"roleId":"角色key","text":"台词"}`，或无角色配角 `{"speaker":"名字","text":"…","voice":"none"}`；有台词时 `video.soundMode` 必须是 `av` |
| `shots[].voiceRole`、`offscreen` | 提示词里用 `<d>` 写台词时的说话角色；不出镜只出声的角色 |

「编辑剧集」可以随时改；删掉的镜头未提交的任务会取消，已出的版本保留。

## 自动检查

- **关键帧**：insightface（与 PuLID 同一套 antelopev2 检测器，CPU 运行）算和角色脸的相似度，并提示「没检测到人脸 / 检测到多张脸 / 差别较大」。同一人物的不同镜头实测约 0.67–0.73。
- **视频**：PyAV 读时长、有无音轨、近黑帧、定格比例。
- 检查只是初筛：表演、动作对不对、有没有听懂提示词，仍要人看。

## 边界

- 一张关键帧只锁一张脸，两人同框时另一个人不锁脸。
- 对白和角色主声音用的是画布同一个编译器（Subject/Picture/Audio 编号和台词写法与画布节点一致）。首尾帧续拍、时间锚点、参考视频还没接入，需要这些的镜头先继续用画布队列。
- 2026-11-08 已做真实 GPU 小批验收：关键帧约 64 秒/张、人脸相似度 0.76–0.82、构图跟分镜；理解优先 5 秒视频 211 秒、显存峰值约 15.4GB。对白镜头、16:9、多人同框和整集合成还没在 GPU 上测，第一次用这些请小批试。
- 账本在 `runtime/production/episodes/*.json`，素材和成片在 `runtime/production/<剧集ID>/`。不要手改账本。
